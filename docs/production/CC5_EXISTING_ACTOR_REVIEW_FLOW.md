# โฟลว์แก้ชุดและตรวจตัวละคร CC5 ทีละตัว

ใช้กับตัวละครที่สร้างใบหน้าและรูปร่างของเรื่องไว้แล้ว งานสร้างใบหน้าใหม่ใช้ขั้นตอนใน [FACE_TIDMUNZ_PIPELINE.md](FACE_TIDMUNZ_PIPELINE.md)

## 1. เลือกตัวละครและเปิดงานของตัวนั้น

- อ่านใบงานและคำแก้ล่าสุด จัดลำดับตามความสำคัญที่ผู้ใช้ให้ไว้ แล้วเลือกหนึ่งตัวและหนึ่งช่วงวัยต่อรอบ
- รัน `python tools/cc5_production_preflight.py --story STORY_SLUG --runtime` แล้วตรวจว่า CC5 พร้อมและไม่มีงานผู้ใช้ที่ยังไม่ได้บันทึก
- เปิด `.ccProject` ของตัวละครและช่วงวัยที่เลือกจากหลักฐานงานล่าสุด เก็บใบหน้า รูปร่าง และทรงผมไว้ตามโจทย์ของรอบนั้น ถ้าใช้ชุดจากเรื่องอื่น ให้ดึงเฉพาะเสื้อผ้าและลองบนตัวละครของเรื่องปัจจุบัน
- เก็บงานทดลองเป็นไฟล์ใหม่ในเครื่องและใช้ชื่อรอบที่ระบุได้ชัดเจน เช่น ชื่อตัวละคร ช่วงวัย และเลขรอบ

## 2. เลือกจากภาพจริงแล้วลองใน CC5

- ดูภาพตัวละครจากงานเดิมบน Drive และ Thumbnail ในแค็ตตาล็อกที่มีอยู่ก่อนเลือก ใช้รหัส Asset หรือชื่อชิ้น Mesh เป็นตัวตามรอยไฟล์หลังเห็นทรงจริง
- เลือกรูปทรงตามยุค งาน ฐานะ และวัย เปรียบเทียบความยาวแขน คอเสื้อ ทรงขา ผ้าซิ่น และทรงผมกับตัวที่ผู้ใช้เห็นไปแล้ว ถ้าผู้ใช้ขอเปลี่ยน Texture อย่างเดียว ให้เปลี่ยนผิวของชิ้นเดิมในโปรเจกต์ที่ตรวจแล้ว
- เมื่อเสื้อผ้าอยู่ใน `.iAvatar` ต้นแบบ ให้แยกชิ้นเสื้อผ้าที่จำเป็นเป็น `.iCloth` ด้วย CC5 แล้วบันทึกต้นทางและภาพอ้างอิง การแยกที่ทดสอบสำเร็จใช้ `RLPy.RFileIO.SaveFile(cloth, …)` กับ `ESaveFileType_AvatarPart` ชื่อ Mesh และชนิดที่บันทึกในไฟล์เก่าอาจคลาดเคลื่อน ให้ยืนยันชิ้นด้วยภาพบนตัวละครจริง
- บันทึก Asset ต้นทาง รูปทรง สีที่ต้องการ Texture และเหตุผลไว้ใน `look.json` ของรอบ ใช้สคริปต์ CC5 ทีละงานและบันทึกฉบับทดลองแยกจากต้นฉบับ

## 3. ตรวจภาพก่อนส่งให้ผู้ใช้

- สำหรับงานใหม่ ให้ CC5 มีเวลาโหลด Texture ผิว เสื้อผ้า และผมอย่างน้อย 15 วินาทีหลังเปิดโมเดล ก่อนเรนเดอร์ภาพตรวจให้เช็กว่าภาพทดสอบมุมหน้าต่อเนื่องกันคงที่สองครั้ง ภาพทดสอบเก็บชั่วคราว ถ้าสียังเปลี่ยนหรือเห็นวัสดุขาวแทน Texture ให้รอหรือแก้สาเหตุก่อนส่งภาพ
- เปิดไฟล์ทดลองกลับใน CC5 แล้วตรวจภาพด้านหน้า ข้าง หลัง และ T-Pose ดูรูปหน้า ผม ชายเสื้อ เอว ตะเข็บ จุดดำ ผิวทะลุ และสีที่เรนเดอร์ได้จริง
- ทดสอบคลิปเดินและยืนยันว่า CC5 ขยับถึงเฟรมที่ขอจริง ตัวอย่างที่ทดสอบแล้วใช้เฟรม 0, 24 และ 44 ตรวจช่วงที่ผ้าเคลื่อนไหว เช่น ใต้แขน เป้ากางเกง เข่า และชายผ้าซิ่น
- ถ้าเห็นผ้าซ้อน ผิวทะลุ หรือชิ้นเสื้อผ้าหาย ให้เก็บรอบนั้นเป็น `FIX` ปรับการแนบหรือเปลี่ยนชิ้นที่มีปัญหา แล้วเรนเดอร์ตรวจซ้ำ ระบุรอยที่ยังเห็นและงบ Polygon ที่ต้องเก็บไว้ในผลตรวจของรอบ
- ทำ PNG รวมมุมตรวจของตัวเดียว ส่งทาง Pic-Gptz ตาม [NTFY_REVIEW.md](NTFY_REVIEW.md) และตรวจใบยืนยันการส่ง ระบุชุด ทรงผม และจุดที่ยังต้องเก็บงานให้ผู้ใช้ตัดสิน
- รอคำตอบของผู้ใช้ เมื่อผู้ใช้ให้ผ่านหรือให้ไปตัวต่อไป ให้จัดการส่งออกและเปิดไฟล์ของตัวที่ตรวจแล้วกลับก่อนเริ่มตัวถัดไป ถ้าพบปัญหาที่ขวางการใช้งาน ให้แจ้งว่าตัวนั้นยังค้างและบอกจุดที่ต้องแก้ ถ้าผู้ใช้ขอเปลี่ยนชุด สี หรือ Texture ให้แก้ตัวเดิมและส่งภาพใหม่ก่อน

## 4. ส่งออกหลังตรวจและเก็บงาน

- ก่อนบันทึก `.iAvatar` ใหม่ ให้รอ Texture และเช็กภาพมุมหน้าซ้ำหลังเปิดโปรเจกต์รอบส่งออก เพราะ CC5 สร้าง Thumbnail ของไฟล์ตอนบันทึก
- แยกการอนุมัติหน้าตาชุดออกจากผลตรวจส่งมอบ ให้สถานะ `PASS` เมื่อผ่าน [Q01–Q10](../CHARACTER_QA_STANDARD.md) รวมถึงส่งออก `.iAvatar` จริง เปิดไฟล์ที่ส่งออกกลับใน CC5 และตรวจสภาพอีกครั้ง
- เก็บ `.ccProject` ทดลอง ภาพตรวจ สคริปต์ และ Log ไว้ในเครื่อง หากใบงานกำหนดให้ส่งบน Drive ให้ลงเฉพาะไฟล์ส่งมอบที่ผ่านตรวจในหมวดเดิม หลังตรวจชื่อ เส้นทาง และไฟล์ปลายทาง

## ตัวอย่างคำสั่งจากเรื่องชัยชนะของคนไม่ยอมแพ้

รันจากโฟลเดอร์โปรเจกต์ ตัวอย่าง PowerShell นี้ใช้สคริปต์ที่อยู่ใน `runs` ของเรื่อง และใช้ชื่อรอบใหม่เพื่อเก็บภาพรอบก่อน

```powershell
$run = 'runs/chai_chana_khon_mai_yom_phae'
# ไฟล์ donor-map มีคีย์ตัวละครเดียว
python -B "$run/review_cast.py" --donor-map "$run/drive_outfit_reuse/chaiyot_young_plain_texture.json" --label 'ชัยยศวัยหนุ่ม_เท็กซ์เจอร์_02'

# ทำภาพจาก views หรือ views_retryN ที่มี runtime.json ตรงกับไฟล์รอบที่ตรวจ
$fit = "$run/cast_fittings/ชัยยศวัยหนุ่ม_เท็กซ์เจอร์_02/chaiyot_young"
python -B "$run/make_actor_review.py" "$fit/views" 'ชัยยศ — วัยหนุ่ม' "$fit/review.png"

# ใช้หลังตรวจและเก็บงานรอบที่จะส่งมอบ
python -B "$run/review_cast.py" --export-reviewed chaiyot_young --label 'ชัยยศวัยหนุ่ม_เท็กซ์เจอร์_02'
```

- `review_cast.py --fit ACTOR --label LABEL` ใช้เมื่อเลือกชุดจากแค็ตตาล็อกและมีตัวนั้นในรายการของสคริปต์ ทุกคำสั่งต้องระบุโหมด ชื่อตัวละครเดียว และชื่อรอบ สคริปต์ตรวจจำนวนตัวละครใน donor map ก่อนเปิด CC5
- `qa_extract_outfits.py` รับ Manifest ของต้นแบบที่เลือกผ่าน `qa_bridge.py` และบันทึก `pieces/<donor>/extraction.json` ในเครื่อง จากนั้น `qa_fit_cast.py` ใช้ชิ้นที่เลือก และ `qa_cast_runtime.py` สร้างภาพพร้อม `runtime.json`
- ภาพและหลักฐานอยู่ใน `cast_fittings/<label>/<actor>/` ส่วนไฟล์ตรวจส่งออกอยู่ใน `export_check/` ใช้ `tools.cc5_production_flow.ntfy_send` สำหรับส่ง PNG และเก็บใบยืนยันแบบตัดรายการซ้ำ

## ใช้ Ai-cc5

จาก PowerShell ในโฟลเดอร์โปรเจกต์ ใช้ .\Ai-cc5.cmd เพื่อดูสถานะและคำสั่งถัดไป ถ้าโฟลเดอร์โปรเจกต์อยู่ใน PATH พิมพ์ Ai-cc5 ได้โดยตรง

1. Ai-cc5 use <story> [actor] เลือกเรื่องและ actor key ของช่วงวัย เช่น father_main เมื่อต้องการ donor map ใช้ --donor-map <file> พร้อม actor มี --label <label> สำหรับกำหนดชื่อรอบ
2. Ai-cc5 do ทำขั้นถัดไปหนึ่งขั้น ใช้ do --dry เพื่อดูล่วงหน้า ขั้น 3, 4, 5 และ 9 ต้องได้อนุญาตจากผู้ใช้ก่อนใช้ do --allow-cc5; ปุ่มอนุมัติใน Preview ให้สิทธิ์ทำส่งออก QA tidy และเริ่มตัวถัดไปที่เตรียมพร้อมหนึ่งตัวจนถึงส่งภาพ
3. ขั้น 8 รอให้ผู้ใช้ตรวจภาพ `review.png` และใบยืนยันใน Preview แล้วกด «อนุมัติและทำต่อ» หรือใช้ทางเลือกพิมพ์อนุมัติในแชต Codex แล้วรัน Ai-cc5 approve --said "<ข้อความเดิม>" โปรแกรมตรวจข้อความผู้ใช้ล่าสุดใน session นั้น ปุ่ม Preview ใช้ไฟล์สถานะชุดเดียวกับ CLI และจะแสดงต่อเมื่อใบยืนยันตรงกับภาพรอบปัจจุบัน
4. การกดปุ่มอนุมัติใน Preview ให้สิทธิ์ Ai-cc5 ทำขั้นส่งออก เปิดกลับ QA และ tidy ของตัวปัจจุบันต่อเนื่อง แล้วเริ่มตัวถัดไปที่เตรียมไว้หนึ่งตัวโดยไม่ขออนุญาตซ้ำ ระบบหยุดเมื่อพบ FAIL หรือหลักฐานไม่ครบ
4. ขั้น 10 ให้ AI เปิดภาพทั้งหมดและหลักฐาน export_check แล้วกรอกผลรายข้อพร้อมคำอธิบายที่ตรวจได้ใน qa.json ของรอบ จากนั้นรัน do เพื่อยืนยัน Q01–Q10 และรันอีกครั้งเพื่อ tidy
5. ถ้าผู้ใช้ขอแก้หลังส่งภาพ หรือ QA มีข้อ FIX/REVIEW ใช้ use เรื่องและ actor เดิมพร้อม --label ใหม่ เพื่อเริ่มรอบใหม่และเก็บหลักฐานเก่าไว้

ใช้ status, steps, rules <เลขหรือชื่อขั้น>, log และ window เพื่อตรวจงาน หน้าต่างและ CLI อ่าน runs/<story>/ai_cc5_state.json เหมือนกัน หลักฐานส่งภาพ QA และ FAIL อยู่ใน runs/<story>/ai_cc5/<label>/ หากงาน CC5 ค้าง ให้ตรวจ log และยืนยันว่างก่อนใช้ do --recover คำสั่งนี้ปลดสถานะค้างเพื่อให้ตรวจหลักฐานของขั้นเดิมอีกครั้ง

เรื่องที่ใช้ต้องมี CAST_QA_INVENTORY.json, qa_bridge.py, make_actor_review.py และ review_cast.py ใน runs/<story>/ สคริปต์ review_cast ต้องรองรับ --fit-only, --render-reviewed --expected-source และ --exact เพื่อแยกลองชุด เรนเดอร์ และตรวจหลังส่งออก เรื่องที่มีสคริปต์พร้อมในเครื่องนี้คือ chai_chana_khon_mai_yom_phae ส่วนเรื่องอื่นต้องเตรียมสูตรชุดและต้นฉบับของแต่ละช่วงวัยก่อน

Ai-cc5 doctor ตรวจตำแหน่ง CC5, Python, Blender, Tidmunz Studio, คลัง และ cc5_jobs ตั้งค่าตำแหน่งเฉพาะเครื่องใน config.json ด้วยคีย์ cc5, cc5_animation และ cc5_motorbike ตามจำเป็น ส่วน Ai-cc5 update ติดตั้งไฟล์โปรแกรมจาก GitHub Release โดยข้ามโฟลเดอร์งานและค่าของเครื่อง ใช้ version ดูรุ่นท้องถิ่น

ทดสอบโดยไม่เปิด CC5 ด้วย python -B -m unittest discover -s tools -p test_ai_cc5.py

### เตรียมเรื่องใหม่

เมื่อ AI รับเรื่องด้วย Ai-cc5 use ให้เปิดแท็บ «เตรียมเรื่อง» ใน Preview แท็บนี้แสดง รับบรีฟ → วิเคราะห์เรื่อง → ออกแบบตัวละคร → ตรวจความพร้อม ใช้ปุ่มเปิดโฟลเดอร์หรือเปิดเอกสารแต่ละขั้นโดยตรง หรือรัน Ai-cc5 prepare เพื่อดูผลเดียวกันจาก CLI

แฟ้มของเรื่องอยู่ใน runs/<story>/prepare_story/ ร่างเรื่องอ้าง production_stage = planning ใน stories/<story>.json ขั้นพรีวิวใช้กับตัวละครที่มีต้นฉบับ CC5 และผ่านเกตเตรียมงานแล้ว

Preview อ่านเฉพาะเรื่องล่าสุดจากตัวเลือกงานกลาง และนับตัวละครแยกตามช่วงวัยจากรายการผลิตใน manifest จำนวนตัวที่เสร็จเพิ่มเมื่อปิดรอบสำเร็จหลัง QA และ tidy เรื่องที่ยังไม่สรุปนักแสดงใช้ยอดจากบรีฟทั้งเรื่อง โดยแสดงช่วงและกลุ่มที่ยังไม่กำหนดจำนวนตามข้อมูลในบรีฟ
